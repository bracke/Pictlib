# Invariant Registry

| ID | Description | Enforced By | Coverage | Proof Expectation |
| --- | --- | --- | --- | --- |
| SEC-OVERFLOW-001 | Input-derived sizes are added and multiplied with overflow checks before they bound a read, skip or allocation. | `Pictlib.Internal.Checked_Arithmetic` | `arithmetic.overflow`, `enumeration.limits` | Proof-designated (M7) |
| STREAM-001 | Exact reads, skips and writes complete across short transfers and reject zero progress deterministically. | `Pictlib.Streams` | `streams.*`, `enumeration.short_reads`, `decoder.source_failure` | Runtime checked |
| BYTES-001 | Multi-byte values are big-endian; coordinates and Fixed values are two's complement; failures name the opcode being read. | `Pictlib.Internal.Bytes` | `bytes.*` | Runtime checked |
| OPCODE-001 | Every opcode 16#0000#..16#FFFF# has exactly one data-length rule and a reserved flag consistent with Inside Macintosh Appendix A. | `Pictlib.Opcodes` | `opcodes.*` | Proof-designated (M7) |
| CONTAINER-001 | The 512-byte file header is detected without seeking within a 528-byte look-ahead that respects the picture byte limit; the policy decides where the version opcode must be. | `Pictlib.Internal.Container`, `Pictlib.Internal.Picture_Stream` | `container.file_header.*`, `enumeration.limits` | Runtime checked |
| CONTAINER-002 | The frame is non-empty and within the frame limits before any opcode is read; HeaderOp versions -1 and -2 are parsed, anything else fails strictly. | `Pictlib.Internal.Container` | `container.frame.invalid`, `container.v2.*`, `container.header_op.*` | Runtime checked |
| STREAM-002 | Version 2 opcodes start at even picture offsets; version 1 opcodes are unaligned. | `Pictlib.Internal.Opcode_Reader` | `enumeration.v1.stream`, `enumeration.v2.every_rule`, `enumeration.pixel_data.layouts` | Runtime checked |
| STREAM-003 | Each opcode's data is consumed by its structure (regions, polygons, pixel patterns, color tables, packed and unpacked rows) within the per-opcode, region, polygon, opcode-count and picture byte limits; reported data lengths exclude pad bytes. | `Pictlib.Internal.Opcode_Reader` | `enumeration.pixel_data.layouts`, `enumeration.malformed.*`, `enumeration.limits` | Runtime checked |
| STREAM-004 | End of input between opcodes is a missing end opcode (strict failure, lenient warning); inside an opcode it is always a failure carrying the opcode, ordinal and row. | `Pictlib.Internal.Opcode_Reader`, `Pictlib.Decoding` | `enumeration.malformed.truncation_and_end` | Runtime checked |
| META-001 | Retained metadata never exceeds the item and byte budgets: a strict decoder fails, a lenient one drops the item with a Data_Loss warning. | `Pictlib.Internal.Metadata_Store`, `Pictlib.Internal.Opcode_Reader` | `enumeration.metadata.*`, `container.file_header.retention` | Runtime checked |
| DIAG-001 | The warning log never holds more than Max_Warning_Records entries; overflow is reported in its last slot. | `Pictlib.Internal.Diagnostics` | `enumeration.warnings.reserved_and_cap` | Runtime checked |
| STATE-001 | Decoder operations in the wrong state fail with Invalid_State (Operation_Cancelled after Cancel) and change neither state nor last error; Failed, Finished and Stopped are terminal until Reset or Initialize; Finalize is idempotent. | `Pictlib.Decoding` | `decoder.state.*` | Runtime checked |
